# AGENTS.md — Инструкции для AI-агентов

## О проекте

**Job_Search** — проект для поиска работы разработчиком, где весь процесс разработки делегирован AI-агентам. Хозяин проекта (Yevhen Holub) выступает в роли **контролирующего архитектора**: он ставит задачи агентам, проверяет целостность, функциональность и разумное использование ресурсов.

## Ключевой принцип: Спецификация → Реализация → Верификация

Для любого модуля в этом проекте:
1. Сначала создай/измени спецификацию (файл `.md` с описанием требований)
2. Затем реализуй код по спецификации
3. Проверь соответствие результата спецификации

## Структура проекта

```
Job_Search/
├── about_me/          # «Я как продукт»: резюме, pitch, скиллы, ставки
├── portfolio/         # Проекты для портфолио (каждый в своей папке)
├── sources/           # Каталог источников вакансий, платформы, фильтры
├── parsers/           # Боты/парсеры для конкретных платформ + агрегатор
├── monitoring/        # Вотчеры новых вакансий, алерты, дашборд
├── outreach/          # Шаблоны сообщений, автоматизация, трекер диалогов
├── packaging/         # Упаковка разработчика: CV, LinkedIn, соц.доказательства
├── pipeline/          # Оркестрация всего процесса поиска
├── analytics/         # Воронка, статистика, выводы
├── README.md          # Точка входа для человека
└── AGENTS.md          # Этот файл — точка входа для AI-агента
```

## Модули и их назначение

### about_me/
Централизованное хранилище всей информации о разработчике. Содержит:
- `profile.md` — полное резюме: опыт, технологии, проекты, образование
- `ai_pitch.md` — уникальное торговое предложение: как именно используется AI в работе
- `portfolio_plan.md` — план проектов, которые стоит сделать для портфолио
- `rates.md` — ставки для разных рынков (hourly, fixed, retainer)

**При работе с этим модулем:** все данные должны быть консистентны. Если изменилось резюме — обнови pitch и rates. Файлы в этом модуле — источники правды для всех остальных модулей.

### portfolio/
Готовые проекты для демонстрации. Каждый проект в отдельной папке:
```
portfolio/project_name/
├── README.md          # Описание, технологии, что решено
├── AGENTS.md          # Инструкции по доработке этого проекта
├── src/               # Исходный код
├── demo/              # Демо (скриншоты, GIF, ссылка)
└── case_study.md      # Кейс: проблема → решение → результат
```

### sources/
Каталог всех источников вакансий и заданий:
- `registry.md` — список всех известных источников с оценкой эффективности
- `platforms/` — конфигурация и особенности каждой платформы
- `filters.md` — критерии фильтрации (релевантные технологии, бюджет, тип работы)

### parsers/
Автономные боты/парсеры для извлечения вакансий:
- `upwork_bot/` — парсер Upwork RSS/API
- `linkedin_scraper/` — скрэйпер LinkedIn Jobs
- `aggregator/` — собирает данные со всех парсеров в единый формат

### monitoring/
Отслеживание новых вакансий и уведомления:
- `watcher/` — сервис для периодической проверки источников
- `alerts/` — настройка каналов уведомлений (Telegram, email)
- `dashboard/` — CLI или веб-интерфейс для просмотра текущих вакансий

### outreach/
Коммуникации с нанимателями:
- `templates/` — шаблоны сообщений для разных сценариев (cover letter, follow-up, cold outreach, negotiation, rejection response)
- `automation/sender/` — автоматическая отправка сообщений
- `automation/scheduler/` — планировщик последовательных касаний
- `tracker/` — отслеживание статуса каждого диалога (CRM-lite)

### packaging/
Всё, что касается представления разработчика:
- `cv_variants/` — разные версии CV под разные ниши/технологии
- `linkedin_optimization.md` — план оптимизации LinkedIn профиля
- `social_proof/` — кейсы, отзывы, метрики успешных проектов
- `personal_website/` — план и контент для личного сайта

### pipeline/
Оркестрация всего процесса:
- `config.yaml` — общий конфиг (настройки раундов, пороги алертов, каналы)
- `orchestrator/` — скрипты, запускающие парсеры → мониторинг → алерты → outreach

### analytics/
Измерение эффективности:
- `funnel.md` — описание воронки и целевых метрик
- `stats/` — скрипты для сбора статистики
- `insights.md` — выводы и рекомендации по улучшению стратегии

## Стиль работы

1. **Markdown-first** — все спецификации, планы, резюме в `.md`
2. **Консистентность** — данные в `about_me/` используются всеми модулями; изменения там должны отражаться в шаблонах, питчах, CV
3. **Автономность модулей** — каждый парсер/бот/скрэйпер можно запустить отдельно
4. **Единый формат данных** — все вакансии от разных парсеров приводятся к одному формату (определён в `parsers/aggregator/schema.md`)
5. **Никаких секретов в репозитории** — API-ключи, пароли, токены хранятся в `.env` (в `.gitignore`)

## Workflow типовой задачи

Когда получаешь задачу типа «добавь парсер для платформы X»:
1. Изучи `sources/platforms/X.md` (особенности платформы)
2. Создай `parsers/X_bot/README.md` (спецификация)
3. Реализуй код
4. Интегрируй с `aggregator`
5. Добавь в `monitoring/watcher` расписание проверок
6. Обнови `sources/registry.md`
